# ==============================================================================
# High-Availability Kubernetes Cluster on Incus or LXD - Step-by-Step Guide
# Note: Add 'sudo' where needed. The user is expected to provide sudo password.
# Static IP addresses (VIP, BRIDGE_IPV4, BRIDGE_IPV6, NODE1_IP, NODE2_IP, NODE3_IP), Ubuntu release
# (UBUNTU_VERSION), and software versions (KUBERNETES_VERSION, CILIUM_VERSION)
# are configured in 'inventory.txt'.
# ==============================================================================

1. Install Container Engine:
   - For Incus (Recommended default):
     sudo apt-get install -y incus
     (Ensure Zabbly repository is added if on standard Ubuntu 24.04)
   - For LXD:
     sudo snap install lxd

2. Configure Group Membership:
   - For Incus:
     sudo usermod -aG incus-admin $USER
     (Activate group in current shell without logout: sg incus-admin)
   - For LXD:
     sudo usermod -aG lxd $USER
     (Activate group in current shell without logout: sg lxd)

3. Disable UFW on host machine if present:
   sudo ufw disable

4. Configure kernel modules on host:
   Overwrite /etc/modules-load.d/k8s.conf (do not append) to contain only the specified entries:
     sudo tee /etc/modules-load.d/k8s.conf <<EOF
overlay
br_netfilter
nf_conntrack
EOF

   And load these modules into the current host system:
     sudo modprobe overlay
     sudo modprobe br_netfilter
     sudo modprobe nf_conntrack

5. Configure sysctl settings on host:
   Overwrite /etc/sysctl.d/99-k8s.conf (do not append) to contain only the specified entries:
     sudo tee /etc/sysctl.d/99-k8s.conf <<EOF
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

   And load settings into the current host system:
     sudo sysctl --system

6. Initialize container engine with preseed configuration:
   - For Incus:
     sed -e 's|\${BRIDGE}|incusbr0|g' -e 's|\${STORAGE_POOL_DIR}|/var/lib/incus/storage-pools/default|g' -e 's|\${BRIDGE_IPV4}|10.67.38.1|g' -e 's|\${BRIDGE_IPV6}|fd42:51e5:ef75:abeb::1|g' container-engine-init-config | incus admin init --preseed
   - For LXD:
     sed -e 's|\${BRIDGE}|lxdbr0|g' -e 's|\${STORAGE_POOL_DIR}|/var/snap/lxd/common/lxd/storage-pools/default|g' -e 's|\${BRIDGE_IPV4}|10.67.38.1|g' -e 's|\${BRIDGE_IPV6}|fd42:51e5:ef75:abeb::1|g' container-engine-init-config | lxd init --preseed

7. Configure Docker and bridge iptables coexistence (if Docker is running):
   - For Incus:
     sudo iptables -I DOCKER-USER -i incusbr0 -j ACCEPT
     sudo iptables -I DOCKER-USER -o incusbr0 -j ACCEPT
     sudo iptables -t nat -A POSTROUTING -s 10.67.38.0/24 ! -d 10.67.38.0/24 -j MASQUERADE
     sudo netfilter-persistent save
   - For LXD:
     sudo iptables -I DOCKER-USER -i lxdbr0 -j ACCEPT
     sudo iptables -I DOCKER-USER -o lxdbr0 -j ACCEPT
     sudo iptables -t nat -A POSTROUTING -s 10.67.38.0/24 ! -d 10.67.38.0/24 -j MASQUERADE
     sudo netfilter-persistent save

8. Create and configure container profile 'k8s':
   - For Incus:
     incus profile create k8s 2>/dev/null || true
     sed -e 's|\${BRIDGE}|incusbr0|g' -e 's|\${LIMITS_CPU}|4|g' -e 's|\${LIMITS_MEMORY}|4GB|g' k8s-container-profile-config | incus profile edit k8s
   - For LXD:
     lxc profile create k8s 2>/dev/null || true
     sed -e 's|\${BRIDGE}|lxdbr0|g' -e 's|\${LIMITS_CPU}|4|g' -e 's|\${LIMITS_MEMORY}|4GB|g' k8s-container-profile-config | lxc profile edit k8s

9. Launch and start container (node1):
   - For Incus:
     incus launch images:ubuntu/24.04 node1 --profile k8s -d eth0,ipv4.address=10.67.38.87
     incus start node1
   - For LXD:
     lxc launch ubuntu:24.04 node1 --profile k8s -d eth0,ipv4.address=10.67.38.87
     lxc start node1

10. Configure SSH user, sudoers, and /etc/hosts for node1:
    - For Incus:
      incus exec node1 -- useradd -m -s /bin/bash "$USER"
      incus exec node1 -- usermod -aG sudo "$USER"
      echo "$USER:your_password" | incus exec node1 -- chpasswd
      incus exec node1 -- bash -c "mkdir -p /etc/sudoers.d && echo '$USER ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/90-$USER"
      incus exec node1 -- chmod 440 "/etc/sudoers.d/90-$USER"
      incus exec node1 -- mkdir -p "/home/$USER/.ssh"
      incus file push ~/.ssh/id_ed25519.pub "node1/home/$USER/.ssh/authorized_keys"
      incus exec node1 -- chown -R "$USER:$USER" "/home/$USER/.ssh"
      incus exec node1 -- chmod 700 "/home/$USER/.ssh"
      incus exec node1 -- chmod 600 "/home/$USER/.ssh/authorized_keys"
      incus exec node1 -- apt-get update -qq
      incus exec node1 -- apt-get install -y -qq openssh-server
      incus exec node1 -- systemctl enable --now ssh
    - For LXD:
      lxc exec node1 -- useradd -m -s /bin/bash "$USER"
      lxc exec node1 -- usermod -aG sudo "$USER"
      echo "$USER:your_password" | lxc exec node1 -- chpasswd
      lxc exec node1 -- bash -c "mkdir -p /etc/sudoers.d && echo '$USER ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/90-$USER"
      lxc exec node1 -- chmod 440 "/etc/sudoers.d/90-$USER"
      lxc exec node1 -- mkdir -p "/home/$USER/.ssh"
      lxc file push ~/.ssh/id_ed25519.pub "node1/home/$USER/.ssh/authorized_keys"
      lxc exec node1 -- chown -R "$USER:$USER" "/home/$USER/.ssh"
      lxc exec node1 -- chmod 700 "/home/$USER/.ssh"
      lxc exec node1 -- chmod 600 "/home/$USER/.ssh/authorized_keys"
      lxc exec node1 -- apt-get update -qq
      lxc exec node1 -- apt-get install -y -qq openssh-server
      lxc exec node1 -- systemctl enable --now ssh
    - Map node IPs in /etc/hosts on both the host and inside node1:
      echo -e "10.67.38.87\tnode1\n10.67.38.221\tnode2\n10.67.38.211\tnode3" | sudo tee -a /etc/hosts

11. On node1:
    i)   Install containerd:
         sudo apt-get update
         sudo apt-get install -y ca-certificates curl
         sudo install -m 0755 -d /etc/apt/keyrings
         sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
         sudo chmod a+r /etc/apt/keyrings/docker.asc
         echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | sudo tee /etc/apt/sources.list.d/docker.list
         sudo apt-get update
         sudo apt-get install -y containerd.io

    ii)  Generate default containerd configuration:
         sudo rm -rf /etc/containerd/config.toml
         sudo mkdir -p /etc/containerd
         containerd config default | sudo tee /etc/containerd/config.toml
    iii) In the generated /etc/containerd/config.toml, update:
         - SystemdCgroup = true
         - disabled_plugins = []
    iv)  Reload systemd daemon and restart containerd:
         sudo systemctl daemon-reload
         sudo systemctl restart containerd

    v)   Install Kubernetes packages (kubelet, kubeadm, kubectl, cri-tools):
         sudo apt-get update
         sudo apt-get install -y apt-transport-https ca-certificates curl gpg
         sudo install -m 0755 -d /etc/apt/keyrings
         curl -fsSL "https://pkgs.k8s.io/core:/stable:/v1.37/deb/Release.key" | sudo gpg --dearmor --yes -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
         echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.37/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list
         sudo apt-get update
         sudo apt-get install -y kubelet kubeadm kubectl cri-tools
         sudo apt-mark hold kubelet kubeadm kubectl cri-tools
         sudo systemctl enable --now kubelet

    vi)  Pull images with kubeadm and determine the pause image version:
         sudo kubeadm config images pull
         (Check which version of pause image is specified)
    vii) Update the sandbox image in /etc/containerd/config.toml to match this version:
         e.g. sandbox = 'registry.k8s.io/pause:3.10.2'
    viii) Reload systemd daemon and restart containerd:
         sudo systemctl daemon-reload
         sudo systemctl restart containerd

12. Clone node2 and node3 from node1:
    - For Incus:
      i)   Stop node1:
           incus stop node1
      ii)  Copy node2 and node3, assign static IP addresses:
           incus copy node1 node2
           incus config device set node2 eth0 ipv4.address 10.67.38.221
           incus copy node1 node3
           incus config device set node3 eth0 ipv4.address 10.67.38.211
      iii) Start all three containers:
           incus start node1 node2 node3
      iv)  Set hostnames and regenerate unique machine-ids:
           incus exec node2 -- bash -c "echo node2 > /etc/hostname && hostname node2"
           incus exec node2 -- bash -c "rm -f /etc/machine-id /var/lib/dbus/machine-id && systemd-machine-id-setup"
           incus exec node3 -- bash -c "echo node3 > /etc/hostname && hostname node3"
           incus exec node3 -- bash -c "rm -f /etc/machine-id /var/lib/dbus/machine-id && systemd-machine-id-setup"
      v)   Verify SSH connectivity to all nodes.

    - For LXD:
      i)   Stop node1:
           lxc stop node1
      ii)  Copy node2 and node3, assign static IP addresses:
           lxc copy node1 node2
           lxc config device set node2 eth0 ipv4.address 10.67.38.221
           lxc copy node1 node3
           lxc config device set node3 eth0 ipv4.address 10.67.38.211
      iii) Start all three containers:
           lxc start node1 node2 node3
      iv)  Set hostnames and regenerate unique machine-ids:
           lxc exec node2 -- bash -c "echo node2 > /etc/hostname && hostname node2"
           lxc exec node2 -- bash -c "rm -f /etc/machine-id /var/lib/dbus/machine-id && systemd-machine-id-setup"
           lxc exec node3 -- bash -c "echo node3 > /etc/hostname && hostname node3"
           lxc exec node3 -- bash -c "rm -f /etc/machine-id /var/lib/dbus/machine-id && systemd-machine-id-setup"
      v)   Verify SSH connectivity to all nodes.

13. For node1 (Bootstrap Control Plane):
    i)    Copy parameterized kubeadm-init-config.yaml to node1.
    ii)   Generate kube-vip static pod manifest on node1:
          KVVERSION=$(curl -sL https://api.github.com/repos/kube-vip/kube-vip/releases | jq -r ".[0].name" 2>/dev/null || echo "v1.3.0")
          sudo ctr image pull ghcr.io/kube-vip/kube-vip:$KVVERSION
          sudo mkdir -p /etc/kubernetes/manifests
          sudo ctr run --rm --net-host ghcr.io/kube-vip/kube-vip:$KVVERSION vip /kube-vip manifest pod \
              --interface eth0 \
              --address 10.67.38.40 \
              --controlplane \
              --services \
              --arp \
              --leaderElection | sudo tee /etc/kubernetes/manifests/kube-vip.yaml
    iii)  Temporarily update hostPath to super-admin.conf in kube-vip manifest:
          sudo sed -i '/hostPath:/{n;s/admin.conf/super-admin.conf/;}' /etc/kubernetes/manifests/kube-vip.yaml
    iv)   Initialize control plane with kubeadm:
          sudo kubeadm init --config ./kubeadm-init-config.yaml --upload-certs --ignore-preflight-errors=SystemVerification
    v)    Note the token, discovery-token-ca-cert-hash, and certificate-key from the command output, e.g.:
          kubeadm join 10.67.38.40:6443 --token <TOKEN> \
              --discovery-token-ca-cert-hash sha256:<HASH> \
              --control-plane --certificate-key <CERT_KEY>
    vi)   Copy /etc/kubernetes/admin.conf to $HOME/.kube/config (as instructed by the command output).
    vii)  Verify API server is reachable and responds properly (e.g. kubectl get nodes).
    viii) Safely revert hostPath back to admin.conf:
          sudo sed -i '/hostPath:/{n;s/super-admin.conf/admin.conf/;}' /etc/kubernetes/manifests/kube-vip.yaml
    ix)   Move /etc/kubernetes/manifests/kube-vip.yaml to /tmp/
    x)    Verify kube-vip pod is terminated.
    xi)   Move /tmp/kube-vip.yaml back to /etc/kubernetes/manifests/
    xii)  Verify kube-vip pod is recreated and ready.
    xiii) Exit out of node1 back to host machine.

14. Copy Kubernetes admin config from node1 to host machine:
    Copy /home/$USER/.kube/config from node1 to $HOME/.kube/config on the host machine so kubectl can be used from the host.

15. Update join configuration files on host:
    Update kubeadm-join-cp-config.yaml with the values noted in step 13.v (token, caCertHashes, certificateKey).

16. For remaining control plane nodes (node2 .. nodeN) - Join Control Plane:
    For each remaining control plane node:
      i)   SCP parameterized kubeadm-join-cp-config.yaml to the node.
      ii)  Run:
           sudo kubeadm join --config ./kubeadm-join-cp-config.yaml --ignore-preflight-errors=SystemVerification
      iii) Copy /etc/kubernetes/admin.conf to $HOME/.kube/config.
      iv)  Exit out of node back to host machine.

17. Distribute kube-vip manifest:
    Copy /etc/kubernetes/manifests/kube-vip.yaml from node1 to /etc/kubernetes/manifests/ on all remaining control plane nodes (node2 .. nodeN).

18. For worker nodes (Join Worker Nodes):
    For each worker node:
      i)   SCP parameterized kubeadm-join-worker-config.yaml to the worker node.
      ii)  Run:
           sudo kubeadm join --config ./kubeadm-join-worker-config.yaml --ignore-preflight-errors=SystemVerification
      iii) Exit out of node back to host machine.

19. Install host tools:
    On the host machine, install:
      - Cilium CLI (from official GitHub release)
      - Helm (from Buildkite APT repository)
      - Kubectl (from official Kubernetes APT repository)

20. Remove control-plane taints from control plane nodes:
    Run on host for each control plane node:
      kubectl taint nodes <node> node-role.kubernetes.io/control-plane-
    (Allows scheduling user and system workloads across control plane nodes)

21. Download Cilium Helm chart (uses $CILIUM_VERSION from inventory.txt):
    helm pull oci://quay.io/cilium/charts/cilium --version ${CILIUM_VERSION}

22. Render Cilium deployment manifest:
    helm template cilium ./cilium-${CILIUM_VERSION}.tgz --namespace kube-system -f ./cilium-deploy.yaml > cilium.yaml

23. Apply Cilium CNI to the cluster:
    kubectl apply -f ./cilium.yaml

24. Wait for Cilium deployment readiness:
    Run 'cilium status --wait' until successful completion (re-run if the command times out while resources initialize).

25. Verify all nodes reach 'Ready' status:
    Check that all 3 nodes (node1, node2, node3) report condition Ready:
      kubectl get nodes -o wide

26. Deploy test workload:
    kubectl apply -f dnsutils.yaml
    Verify cluster networking and DNS resolution.
