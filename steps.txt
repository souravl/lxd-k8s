# ==============================================================================
# High-Availability Kubernetes Cluster on Incus or LXD - Step-by-Step Guide
# Note: Add 'sudo' where needed. The user is expected to provide sudo password.
# The steps below illustrate a 3-node cluster example (node1, node2, node3),
# but the actual number of control plane and worker nodes (NUM_CP, NUM_WORKER),
# static IP addresses (VIP, BRIDGE_IPV4, BRIDGE_IPV6, NODE1_IP, NODE2_IP, ...),
# hardware sizing (LIMITS_CPU, LIMITS_MEMORY), Ubuntu release (UBUNTU_VERSION),
# and software versions (KUBERNETES_VERSION, CILIUM_VERSION) are configured in 'inventory.txt'.
# ==============================================================================

1. Install Container Engine:
   - For Incus (Recommended default):
     # If on standard Ubuntu 24.04 without Incus in default repositories, add Zabbly repo:
     sudo mkdir -p /etc/apt/keyrings
     sudo curl -fsSL https://pkgs.zabbly.com/key.asc -o /etc/apt/keyrings/zabbly.asc
     sudo sh -c 'cat <<EOF > /etc/apt/sources.list.d/zabbly-incus-stable.sources
Enabled: yes
Types: deb
URIs: https://pkgs.zabbly.com/incus/stable
Suites: $(. /etc/os-release && echo ${VERSION_CODENAME})
Components: main
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/zabbly.asc
EOF'
     sudo apt-get update -qq
     sudo apt-get install -y incus
   - For LXD:
     sudo snap install lxd

2. Configure Group Membership:
   - For Incus:
     sudo usermod -aG incus-admin $USER
     (Activate group in current shell without logout: sg incus-admin)
   - For LXD:
     sudo usermod -aG lxd $USER
     (Activate group in current shell without logout: sg lxd)

3. Disable UFW on host machine if present:
   sudo ufw disable

4. Configure kernel modules on host:
   Overwrite /etc/modules-load.d/k8s.conf (do not append) to contain only the specified entries:
     sudo tee /etc/modules-load.d/k8s.conf <<EOF
overlay
br_netfilter
nf_conntrack
EOF

   And load these modules into the current host system:
     sudo modprobe overlay
     sudo modprobe br_netfilter
     sudo modprobe nf_conntrack

5. Configure sysctl settings on host:
   Overwrite /etc/sysctl.d/99-k8s.conf (do not append) to contain only the specified entries:
     sudo tee /etc/sysctl.d/99-k8s.conf <<EOF
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

   And load settings into the current host system:
     sudo sysctl --system

6. Initialize container engine with preseed configuration
   (the deployment script embeds this configuration instead of reading the file; container-engine-init-config.yaml in backup/ is a reference copy):
   - For Incus:
     sed -e 's|\${BRIDGE}|incusbr0|g' -e 's|\${STORAGE_POOL_DIR}|/var/lib/incus/storage-pools/default|g' -e 's|\${BRIDGE_IPV4}|10.67.38.1|g' -e 's|\${BRIDGE_IPV6}|fd42:51e5:ef75:abeb::1|g' backup/container-engine-init-config.yaml | incus admin init --preseed
   - For LXD:
     sed -e 's|\${BRIDGE}|lxdbr0|g' -e 's|\${STORAGE_POOL_DIR}|/var/snap/lxd/common/lxd/storage-pools/default|g' -e 's|\${BRIDGE_IPV4}|10.67.38.1|g' -e 's|\${BRIDGE_IPV6}|fd42:51e5:ef75:abeb::1|g' backup/container-engine-init-config.yaml | lxd init --preseed

7. Configure Docker and bridge iptables coexistence (if Docker is running):
   - For Incus:
     sudo iptables -I DOCKER-USER -i incusbr0 -j ACCEPT
     sudo iptables -I DOCKER-USER -o incusbr0 -j ACCEPT
     sudo iptables -t nat -A POSTROUTING -s 10.67.38.0/24 ! -d 10.67.38.0/24 -j MASQUERADE
     sudo DEBIAN_FRONTEND=noninteractive apt-get install -y -qq iptables-persistent
     sudo netfilter-persistent save
   - For LXD:
     sudo iptables -I DOCKER-USER -i lxdbr0 -j ACCEPT
     sudo iptables -I DOCKER-USER -o lxdbr0 -j ACCEPT
     sudo iptables -t nat -A POSTROUTING -s 10.67.38.0/24 ! -d 10.67.38.0/24 -j MASQUERADE
     sudo DEBIAN_FRONTEND=noninteractive apt-get install -y -qq iptables-persistent
     sudo netfilter-persistent save

8. Create and configure container profile 'k8s'
   (the deployment script embeds this configuration instead of reading the file; k8s-container-profile-config.yaml in backup/ is a reference copy):
   - For Incus:
     incus profile create k8s 2>/dev/null || true
     sed -e 's|\${BRIDGE}|incusbr0|g' -e 's|\${LIMITS_CPU}|4|g' -e 's|\${LIMITS_MEMORY}|4GB|g' backup/k8s-container-profile-config.yaml | incus profile edit k8s
   - For LXD:
     lxc profile create k8s 2>/dev/null || true
     sed -e 's|\${BRIDGE}|lxdbr0|g' -e 's|\${LIMITS_CPU}|4|g' -e 's|\${LIMITS_MEMORY}|4GB|g' backup/k8s-container-profile-config.yaml | lxc profile edit k8s

9. Launch and start container (node1):
   - For Incus:
     incus launch images:ubuntu/24.04 node1 --profile k8s -d eth0,ipv4.address=10.67.38.10
     incus start node1
   - For LXD:
     lxc launch ubuntu:24.04 node1 --profile k8s -d eth0,ipv4.address=10.67.38.10
     lxc start node1

10. Configure SSH user, sudoers, and /etc/hosts for node1:
    (The script uses ~/.ssh/id_ed25519.pub, else ~/.ssh/id_rsa.pub. If neither exists, it generates ~/.ssh/id_ed25519. If a private key
     (id_ed25519 or id_rsa) exists without its .pub file, the script stops with an error and prints the command to create it:
     ssh-keygen -y -f ~/.ssh/id_ed25519 > ~/.ssh/id_ed25519.pub
     The script checks whether passwordless SSH to node1 already works with "ssh -o ConnectTimeout=2 -o ServerAliveInterval=2
     -o ServerAliveCountMax=3 $USER@node1 true"; if it does, it skips the user, sudoers and SSH server setup below.)
    - For Incus:
      incus exec node1 -- useradd -m -s /bin/bash "$USER"
      incus exec node1 -- usermod -aG sudo "$USER"
      echo "$USER:your_password" | incus exec node1 -- chpasswd
      incus exec node1 -- bash -c "mkdir -p /etc/sudoers.d && echo '$USER ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/90-$USER"
      incus exec node1 -- chmod 440 "/etc/sudoers.d/90-$USER"
      incus exec node1 -- mkdir -p "/home/$USER/.ssh"
      incus file push ~/.ssh/id_ed25519.pub "node1/home/$USER/.ssh/authorized_keys"
      incus exec node1 -- chown -R "$USER:$USER" "/home/$USER/.ssh"
      incus exec node1 -- chmod 700 "/home/$USER/.ssh"
      incus exec node1 -- chmod 600 "/home/$USER/.ssh/authorized_keys"
      incus exec node1 -- apt-get update -qq
      incus exec node1 -- apt-get install -y -qq openssh-server
      incus exec node1 -- systemctl enable --now ssh
      incus exec node1 -- bash -c "echo -e '10.67.38.10\tnode1\n10.67.38.20\tnode2\n10.67.38.30\tnode3\n10.67.38.40\tnode4\n10.67.38.50\tnode5' >> /etc/hosts"
    - For LXD:
      lxc exec node1 -- useradd -m -s /bin/bash "$USER"
      lxc exec node1 -- usermod -aG sudo "$USER"
      echo "$USER:your_password" | lxc exec node1 -- chpasswd
      lxc exec node1 -- bash -c "mkdir -p /etc/sudoers.d && echo '$USER ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/90-$USER"
      lxc exec node1 -- chmod 440 "/etc/sudoers.d/90-$USER"
      lxc exec node1 -- mkdir -p "/home/$USER/.ssh"
      lxc file push ~/.ssh/id_ed25519.pub "node1/home/$USER/.ssh/authorized_keys"
      lxc exec node1 -- chown -R "$USER:$USER" "/home/$USER/.ssh"
      lxc exec node1 -- chmod 700 "/home/$USER/.ssh"
      lxc exec node1 -- chmod 600 "/home/$USER/.ssh/authorized_keys"
      lxc exec node1 -- apt-get update -qq
      lxc exec node1 -- apt-get install -y -qq openssh-server
      lxc exec node1 -- systemctl enable --now ssh
      lxc exec node1 -- bash -c "echo -e '10.67.38.10\tnode1\n10.67.38.20\tnode2\n10.67.38.30\tnode3\n10.67.38.40\tnode4\n10.67.38.50\tnode5' >> /etc/hosts"
    - Map node IPs in /etc/hosts on the host machine:
      echo -e "10.67.38.10\tnode1\n10.67.38.20\tnode2\n10.67.38.30\tnode3\n10.67.38.40\tnode4\n10.67.38.50\tnode5" | sudo tee -a /etc/hosts

11. On node1:
    i)   Install containerd:
         sudo apt-get update
         sudo apt-get install -y ca-certificates curl
         sudo install -m 0755 -d /etc/apt/keyrings
         sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
         sudo chmod a+r /etc/apt/keyrings/docker.asc
         sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
         sudo apt-get update
         sudo apt-get install -y containerd.io

    ii)  Generate default containerd configuration:
         sudo rm -rf /etc/containerd/config.toml
         sudo mkdir -p /etc/containerd
         containerd config default | sudo tee /etc/containerd/config.toml
    iii) In the generated /etc/containerd/config.toml, update:
         - SystemdCgroup = true:
           sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml
         - disabled_plugins = [] (ensures CRI plugin is active):
           sudo sed -i 's/disabled_plugins = .*/disabled_plugins = []/g' /etc/containerd/config.toml
    iv)  Reload systemd daemon and restart containerd:
         sudo systemctl daemon-reload
         sudo systemctl restart containerd

    v)   Install Kubernetes packages (kubelet, kubeadm, kubectl, cri-tools):
         sudo apt-get update
         sudo apt-get install -y apt-transport-https ca-certificates curl gpg
         sudo install -m 0755 -d /etc/apt/keyrings
         curl -fsSL "https://pkgs.k8s.io/core:/stable:/v1.37/deb/Release.key" | sudo gpg --dearmor --yes -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
         echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.37/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list
         sudo apt-get update
         sudo apt-get install -y kubelet kubeadm kubectl cri-tools
         sudo apt-mark hold kubelet kubeadm kubectl cri-tools
         sudo systemctl enable --now kubelet

    vi)  Pull images with kubeadm and determine the pause image version:
         sudo kubeadm config images pull
         (Check which version of pause image is specified)
    vii) Update the sandbox image in /etc/containerd/config.toml to match this version:
         sudo sed -i 's|sandbox_image = .*|sandbox_image = "registry.k8s.io/pause:3.10.2"|g' /etc/containerd/config.toml
         sudo sed -i 's|sandbox = .*|sandbox = "registry.k8s.io/pause:3.10.2"|g' /etc/containerd/config.toml
    viii) Reload systemd daemon and restart containerd:
         sudo systemctl daemon-reload
         sudo systemctl restart containerd

12. Clone remaining nodes (node2 .. nodeN) from node1:
    - For Incus:
      i)   Stop node1:
           incus stop node1
      ii)  Copy remaining nodes and assign static IP addresses:
           incus copy node1 node2
           incus config device set node2 eth0 ipv4.address 10.67.38.20
           incus copy node1 node3
           incus config device set node3 eth0 ipv4.address 10.67.38.30
           # (Repeat for any additional control plane or worker nodes, e.g. node4 -> 10.67.38.40, node5 -> 10.67.38.50)
      iii) Start all containers:
           incus start node1 node2 node3
      iv)  Set hostnames, regenerate unique machine-ids, and regenerate SSH host keys:
           incus exec node2 -- bash -c "echo node2 > /etc/hostname && hostname node2"
           incus exec node2 -- bash -c "rm -f /etc/machine-id /var/lib/dbus/machine-id && systemd-machine-id-setup"
           incus exec node2 -- bash -c "rm -f /etc/ssh/ssh_host_* && ssh-keygen -A && systemctl restart ssh"
           incus exec node3 -- bash -c "echo node3 > /etc/hostname && hostname node3"
           incus exec node3 -- bash -c "rm -f /etc/machine-id /var/lib/dbus/machine-id && systemd-machine-id-setup"
           incus exec node3 -- bash -c "rm -f /etc/ssh/ssh_host_* && ssh-keygen -A && systemctl restart ssh"
      v)   Verify SSH connectivity to all nodes and populate host's known_hosts:
           ssh-keyscan -H node1 node2 node3 >> ~/.ssh/known_hosts

    - For LXD:
      i)   Stop node1:
           lxc stop node1
      ii)  Copy remaining nodes and assign static IP addresses:
           lxc copy node1 node2
           lxc config device set node2 eth0 ipv4.address 10.67.38.20
           lxc copy node1 node3
           lxc config device set node3 eth0 ipv4.address 10.67.38.30
           # (Repeat for any additional control plane or worker nodes, e.g. node4 -> 10.67.38.40, node5 -> 10.67.38.50)
      iii) Start all containers:
           lxc start node1 node2 node3
      iv)  Set hostnames, regenerate unique machine-ids, and regenerate SSH host keys:
           lxc exec node2 -- bash -c "echo node2 > /etc/hostname && hostname node2"
           lxc exec node2 -- bash -c "rm -f /etc/machine-id /var/lib/dbus/machine-id && systemd-machine-id-setup"
           lxc exec node2 -- bash -c "rm -f /etc/ssh/ssh_host_* && ssh-keygen -A && systemctl restart ssh"
           lxc exec node3 -- bash -c "echo node3 > /etc/hostname && hostname node3"
           lxc exec node3 -- bash -c "rm -f /etc/machine-id /var/lib/dbus/machine-id && systemd-machine-id-setup"
           lxc exec node3 -- bash -c "rm -f /etc/ssh/ssh_host_* && ssh-keygen -A && systemctl restart ssh"
      v)   Verify SSH connectivity to all nodes and populate host's known_hosts:
           ssh-keyscan -H node1 node2 node3 >> ~/.ssh/known_hosts

13. For node1 (Bootstrap Control Plane):
    i)    Copy parameterized kubeadm-init-config.yaml to node1
          (the deployment scripts embed this configuration instead of reading the file; the file in backup/ is a reference copy):
          Substitute ${NODE1_IP} (10.67.38.10), ${VIP} (10.67.38.250), ${KUBERNETES_FULL_VERSION}
          (the full version of the kubeadm installed on node1, from 'kubeadm version -o short', for example v1.37.2;
           it is set as kubernetesVersion so kubeadm does not look up the latest version on dl.k8s.io), and ${CERT_SANS}
          (a YAML list including 127.0.0.1, localhost, 10.67.38.250, and each control plane's IP and hostname).
          scp kubeadm-init-config.yaml node1:~/kubeadm-init-config.yaml
    ii)   Generate kube-vip static pod manifest on node1 in /tmp/kube-vip.yaml:
          KVVERSION=$(curl -sL https://api.github.com/repos/kube-vip/kube-vip/releases | jq -r ".[0].name" 2>/dev/null || echo "v1.3.0")
          sudo ctr image pull ghcr.io/kube-vip/kube-vip:$KVVERSION
          sudo mkdir -p /etc/kubernetes/manifests
          sudo ctr run --rm --net-host ghcr.io/kube-vip/kube-vip:$KVVERSION vip /kube-vip manifest pod \
              --interface eth0 \
              --address 10.67.38.250 \
              --controlplane \
              --services \
              --arp \
              --leaderElection | sudo tee /tmp/kube-vip.yaml
    iii)  Temporarily update hostPath to super-admin.conf in /tmp/kube-vip.yaml before placing in manifests:
          sudo sed -i '/hostPath:/{n;s/admin.conf/super-admin.conf/;}' /tmp/kube-vip.yaml
          sudo cp -f /tmp/kube-vip.yaml /etc/kubernetes/manifests/kube-vip.yaml
    iv)   Initialize control plane with kubeadm:
          sudo kubeadm init --config ./kubeadm-init-config.yaml --upload-certs --ignore-preflight-errors=SystemVerification
    v)    Note the token, discovery-token-ca-cert-hash, and certificate-key from the command output, e.g.:
          kubeadm join 10.67.38.250:6443 --token <TOKEN> \
              --discovery-token-ca-cert-hash sha256:<HASH> \
              --control-plane --certificate-key <CERT_KEY>
    vi)   Copy /etc/kubernetes/admin.conf to $HOME/.kube/config (as instructed by the command output).
    vii)  Verify API server is reachable and responds properly (e.g. kubectl get nodes).
    viii) Safely revert hostPath back to admin.conf:
          sudo sed -i '/hostPath:/{n;s/super-admin.conf/admin.conf/;}' /etc/kubernetes/manifests/kube-vip.yaml
    ix)   Move /etc/kubernetes/manifests/kube-vip.yaml to /tmp/
    x)    Stop and remove old kube-vip container to force static pod reload:
          sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock stopp $(sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock pods --name kube-vip -q 2>/dev/null) 2>/dev/null || true
          sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock rmp $(sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock pods --name kube-vip -q 2>/dev/null) 2>/dev/null || true
    xi)   Move /tmp/kube-vip.yaml back to /etc/kubernetes/manifests/
    xii)  Verify kube-vip pod is recreated and ready:
          until sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock pods --name kube-vip --state Ready -q 2>/dev/null | grep -q .; do sleep 2; done
          until kubectl get nodes >/dev/null 2>&1; do sleep 2; done
    xiii) Exit out of node1 back to host machine.

14. Copy Kubernetes admin config from node1 to host machine:
    mkdir -p $HOME/.kube
    scp "$USER@node1:/home/$USER/.kube/config" "$HOME/.kube/config"
    chmod 600 "$HOME/.kube/config"
    (Allows managing the cluster with kubectl directly from the host machine).

15. Update join configuration files on host:
    (The deployment scripts embed both join configurations instead of reading the files; the files in backup/ are reference copies.)
    - Update kubeadm-join-cp-config.yaml with the values noted in step 13.v (${JOIN_TOKEN}, ${CA_CERT_HASH}, ${CERT_KEY}, ${VIP}, and target ${NODE_IP}).
    - Update kubeadm-join-worker-config.yaml with ${JOIN_TOKEN}, ${CA_CERT_HASH}, ${VIP}, and target ${NODE_IP}.

16. For remaining control plane nodes (node2 .. node${NUM_CP}) - Join Control Plane:
    For each remaining control plane node:
      i)   SCP parameterized kubeadm-join-cp-config.yaml to the node.
      ii)  Run:
           sudo kubeadm join --config ./kubeadm-join-cp-config.yaml --ignore-preflight-errors=SystemVerification
      iii) Copy /etc/kubernetes/admin.conf to $HOME/.kube/config and set ownership:
           mkdir -p $HOME/.kube
           sudo cp -f /etc/kubernetes/admin.conf $HOME/.kube/config
           sudo chown $(id -u):$(id -g) $HOME/.kube/config
      iv)  Exit out of node back to host machine.

17. Distribute kube-vip manifest:
    Copy /etc/kubernetes/manifests/kube-vip.yaml from node1 to /etc/kubernetes/manifests/ on all remaining control plane nodes (node2 .. node${NUM_CP}).
    (Note: Do NOT distribute kube-vip to worker nodes).

18. For worker nodes (Join Worker Nodes) (if NUM_WORKER > 0):
    For each worker node (node${NUM_CP+1} .. node${TOTAL_NODES}):
      i)   SCP parameterized kubeadm-join-worker-config.yaml to the worker node.
      ii)  Run:
           sudo kubeadm join --config ./kubeadm-join-worker-config.yaml --ignore-preflight-errors=SystemVerification
      iii) Exit out of node back to host machine.

19. Install the certificate check and renewal scripts on the control plane nodes:
    For each control plane node (node1 .. node${NUM_CP}); worker nodes get nothing. The files are in the certs/ folder next to the script:
      i)   SCP check_k8s_certs.sh, renew_k8s_control_plane_certs.sh, check_k8s_certs.service and check_k8s_certs.timer to /tmp on the node.
      ii)  Install the two scripts to /usr/local/bin (mode 0755) and the service and timer to /etc/systemd/system (mode 0644):
           sudo install -m 0755 /tmp/check_k8s_certs.sh /usr/local/bin/check_k8s_certs.sh
           sudo install -m 0755 /tmp/renew_k8s_control_plane_certs.sh /usr/local/bin/renew_k8s_control_plane_certs.sh
           sudo install -m 0644 /tmp/check_k8s_certs.service /etc/systemd/system/check_k8s_certs.service
           sudo install -m 0644 /tmp/check_k8s_certs.timer /etc/systemd/system/check_k8s_certs.timer
      iii) Set DEPLOY_USER in the installed renew_k8s_control_plane_certs.sh to $USER (the script also replaces that user's ~/.kube/config):
           sudo sed -i "s|^DEPLOY_USER=.*|DEPLOY_USER=\"$USER\"|" /usr/local/bin/renew_k8s_control_plane_certs.sh
      iv)  Remove the files from /tmp and enable the timer (it runs the check 2 hours after boot and then every 12 hours as root; the check runs
           renew_k8s_control_plane_certs.sh when a control plane certificate expires within 60 days):
           sudo systemctl daemon-reload
           sudo systemctl enable --now check_k8s_certs.timer
    (renew_k8s_kubelet_client_cert_from_host.sh, which renews the kubelet client certificate of one node, is not installed. Run it by hand on the host.
     Before that, set FIRST_NODE in the script to node1 (the deploy script does this in the repo copy of the script, so it changes the file on every run):
       sed -i "s|^FIRST_NODE=.*|FIRST_NODE=\"node1\"|" certs/renew_k8s_kubelet_client_cert_from_host.sh
       ./certs/renew_k8s_kubelet_client_cert_from_host.sh <node-name>)
    (renew_k8s_control_plane_certs_from_host.sh, which renews the control plane certificates of all control plane nodes from the host, is not installed. Run it by hand on the host.
     Before that, set FIRST_NODE, OTHER_CP_NODES and WORKER_NODES (space separated, may be empty) in the script (the deploy script does this in the repo copy of the script, so it changes the file on every run):
       sed -i -e "s|^FIRST_NODE=.*|FIRST_NODE=\"node1\"|" -e "s|^OTHER_CP_NODES=.*|OTHER_CP_NODES=\"<node2 .. node${NUM_CP}>\"|" -e "s|^WORKER_NODES=.*|WORKER_NODES=\"<worker nodes>\"|" certs/renew_k8s_control_plane_certs_from_host.sh
       ./certs/renew_k8s_control_plane_certs_from_host.sh
     It runs sudo /usr/local/bin/renew_k8s_control_plane_certs.sh on node1, copies /etc/kubernetes/admin.conf of node1 to ~/.kube/config on the host
     (the old one is kept as ~/.kube/_old_kube_config), runs the same renewal script on the other control plane nodes, then copies the new host
     ~/.kube/config to ~/.kube/config of the ssh user and of root on every worker node.)

20. Install host tools:
    On the host machine, install Cilium CLI, Helm, and Kubectl:
    i)   Install Cilium CLI:
         CILIUM_CLI_VERSION=$(curl -s https://raw.githubusercontent.com/cilium/cilium-cli/main/stable.txt)
         CLI_ARCH=amd64; if [ "$(uname -m)" = "aarch64" ]; then CLI_ARCH=arm64; fi
         curl -L --fail --progress-bar "https://github.com/cilium/cilium-cli/releases/download/${CILIUM_CLI_VERSION}/cilium-linux-${CLI_ARCH}.tar.gz" -o /tmp/cilium-linux-${CLI_ARCH}.tar.gz
         sudo tar xzvfC /tmp/cilium-linux-${CLI_ARCH}.tar.gz /usr/local/bin
         rm -f /tmp/cilium-linux-${CLI_ARCH}.tar.gz
    ii)  Install Helm via APT:
         sudo apt-get update -qq && sudo apt-get install -y -qq curl gpg apt-transport-https
         curl -fsSL https://packages.buildkite.com/helm-linux/helm-debian/gpgkey | gpg --dearmor | sudo tee /usr/share/keyrings/helm.gpg > /dev/null
         echo "deb [signed-by=/usr/share/keyrings/helm.gpg] https://packages.buildkite.com/helm-linux/helm-debian/any/ any main" | sudo tee /etc/apt/sources.list.d/helm-stable-debian.list
         sudo apt-get update -qq && sudo apt-get install -y helm
    iii) Install Kubectl via APT:
         curl -fsSL "https://pkgs.k8s.io/core:/stable:/v1.37/deb/Release.key" | sudo gpg --dearmor --yes -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
         echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.37/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list
         sudo apt-get update -qq && sudo apt-get install -y kubectl
         sudo apt-mark hold kubectl

21. Remove control-plane taints from control plane nodes:
    Run on host for each control plane node (node1 .. node${NUM_CP}):
      kubectl taint nodes <node> node-role.kubernetes.io/control-plane-
    (Allows scheduling user and system workloads across control plane nodes)

22. Download Cilium Helm chart (uses $CILIUM_VERSION from inventory.txt):
    helm pull oci://quay.io/cilium/charts/cilium --version ${CILIUM_VERSION}

23. Render Cilium deployment manifest:
    helm template cilium ./cilium-${CILIUM_VERSION}.tgz --namespace kube-system -f ./cilium-deploy.yaml > cilium.yaml

24. Apply Cilium CNI to the cluster:
    kubectl apply -f ./cilium.yaml

25. Wait for Cilium deployment readiness:
    Run 'cilium status --wait' until successful completion (re-run if the command times out while resources initialize).

26. Verify all nodes reach 'Ready' status:
    Wait for all cluster nodes to report condition Ready:
      kubectl wait --for=condition=Ready nodes --all --timeout=300s
      kubectl get nodes -o wide

27. Deploy test workload:
    kubectl apply -f dnsutils.yaml
    kubectl wait --for=condition=Ready pod/dnsutils --timeout=120s || true
    kubectl get pods -A
    Verify cluster networking and DNS resolution.
