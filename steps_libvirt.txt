# ==============================================================================
# High-Availability Kubernetes Cluster on libvirt (KVM VMs) - Step-by-Step Guide
# Note: Add 'sudo' where needed. The user is expected to provide sudo password.
# The steps below illustrate a 3-node cluster example (node1, node2, node3),
# but the actual number of control plane and worker nodes (NUM_CP, NUM_WORKER),
# static IP addresses (VIP, BRIDGE_IPV4, NODE1_IP, NODE2_IP, ...), hardware sizing
# (LIMITS_CPU, LIMITS_MEMORY, LIMITS_DISK), Ubuntu release (UBUNTU_VERSION),
# software versions (KUBERNETES_VERSION, CILIUM_VERSION, LONGHORN_VERSION), and the Longhorn UI port (LONGHORN_PORT)
# are configured in 'inventory.txt'.
# ==============================================================================

1. Install Hypervisor & Virtualization Tools:
   - Install QEMU/KVM, libvirt, virtinst, cloud tools, and chrony on the host:
     sudo apt-get update
     sudo apt-get install -y qemu-kvm libvirt-daemon-system libvirt-clients bridge-utils virtinst libguestfs-tools chrony
   - Ensure the libvirt service is enabled and running:
     sudo systemctl enable --now libvirtd

2. Configure Group Membership:
   - Add current user to libvirt and kvm groups:
     sudo usermod -aG libvirt,kvm $USER
     (Activate group in current shell without logout: newgrp libvirt)
   - Ensure virsh defaults to the system daemon (qemu:///system):
     echo 'export LIBVIRT_DEFAULT_URI="qemu:///system"' >> ~/.bashrc
     export LIBVIRT_DEFAULT_URI="qemu:///system"

3. Disable UFW on host machine if present:
   sudo ufw disable

4. Configure kernel modules on host:
   - Load host network acceleration module for KVM:
     sudo tee /etc/modules-load.d/k8s-libvirt.conf <<EOF
vhost_net
EOF
     sudo modprobe vhost_net
   (Note: Kubernetes networking modules like 'overlay' and 'br_netfilter' run inside the VM guest OS and will be configured in Step 12).

5. Configure sysctl settings on host:
   - Ensure IP forwarding is enabled on the host for bridge NAT routing:
     sudo tee /etc/sysctl.d/99-k8s-libvirt.conf <<EOF
net.ipv4.ip_forward = 1
EOF
     sudo sysctl --system

6. Update libvirt 'default' network (virbr0) configuration:
   - If 'default' network is not already defined in libvirt, define it from template:
     virsh net-info default >/dev/null 2>&1 || sudo virsh net-define /etc/libvirt/qemu/networks/default.xml
   - Export current default network definition:
     virsh net-dumpxml default > default-net.xml
   - Update the gateway IP and dynamic DHCP range in place (keeps virbr0, NAT mode, and bridge settings):
     sed -i 's|192.168.122.1|10.67.38.1|g' default-net.xml
     sed -i 's|192.168.122.2|10.67.38.100|g' default-net.xml
     sed -i 's|192.168.122.254|10.67.38.200|g' default-net.xml
   - Redefine and restart the network once:
     virsh net-define default-net.xml
     virsh net-destroy default
     virsh net-start default
     virsh net-autostart default
   (Note: Node static IPs are NOT hardcoded here; they are registered dynamically at VM creation time in Steps 9 and 13).

7. Configure Docker and bridge iptables coexistence (if Docker is running):
   - Add rules for virbr0 to DOCKER-USER chain and ensure NAT masquerading:
     sudo iptables -I DOCKER-USER -i virbr0 -j ACCEPT
     sudo iptables -I DOCKER-USER -o virbr0 -j ACCEPT
     sudo iptables -t nat -A POSTROUTING -s 10.67.38.0/24 ! -d 10.67.38.0/24 -j MASQUERADE
     sudo DEBIAN_FRONTEND=noninteractive apt-get install -y -qq iptables-persistent
     sudo netfilter-persistent save

8. Download base Ubuntu Cloud Image & prepare directories:
   - Create local directory for cached base cloud images:
     mkdir -p ./images
   - Download Ubuntu 24.04 server cloud image (qcow2 format) if not already present:
     if [ ! -f ./images/ubuntu-24.04-base.qcow2 ]; then
         curl -L -o ./images/ubuntu-24.04-base.qcow2 https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
     fi

9. Launch and start VM (node1):
   - i)   Register node1 static DHCP reservation in libvirt at VM creation time:
          sudo virsh net-update default add ip-dhcp-host "<host mac='52:54:00:10:00:0a' name='node1' ip='10.67.38.10'/>" --live --config
          (Note: The last MAC octet '0a' is the hexadecimal equivalent of the IP's 4th octet '10').
   - ii)  Create node1 disk in /var/lib/libvirt/images/ from base image and resize to $LIMITS_DISK (e.g. 20G or 15G):
          sudo cp ./images/ubuntu-24.04-base.qcow2 /var/lib/libvirt/images/node1.qcow2
          sudo qemu-img resize /var/lib/libvirt/images/node1.qcow2 20G
   - iii) Prepare cloud-init user-data file with $USER, passwordless sudo, and public SSH key.
          If neither ~/.ssh/id_ed25519.pub nor ~/.ssh/id_rsa.pub exists, the script generates ~/.ssh/id_ed25519. If a private key
          (id_ed25519 or id_rsa) exists without its .pub file, the script stops with an error and prints the command to create it:
          ssh-keygen -y -f ~/.ssh/id_ed25519 > ~/.ssh/id_ed25519.pub
          SSH_PUB_KEY=$(cat ~/.ssh/id_ed25519.pub 2>/dev/null || cat ~/.ssh/id_rsa.pub)
          cat <<EOF > cloud-init-user-data.yaml
#cloud-config
hostname: node1
fqdn: node1
users:
  - name: $USER
    gecos: $USER
    groups: sudo
    shell: /bin/bash
    sudo: ALL=(ALL) NOPASSWD:ALL
    ssh_authorized_keys:
      - $SSH_PUB_KEY
EOF
   - iv)  Launch node1 using virt-install:
          sudo virt-install \
            --name node1 \
            --vcpus 4 \
            --memory 4096 \
            --osinfo ubuntu24.04 \
            --disk path=/var/lib/libvirt/images/node1.qcow2,format=qcow2,bus=virtio,cache=none \
            --network network=default,model=virtio,mac=52:54:00:10:00:0a \
            --cloud-init user-data=./cloud-init-user-data.yaml \
            --import \
            --noautoconsole
   - v)   Wait for node1 to finish booting and become reachable over SSH:
          (The polling ssh calls here and in step 13 use "-o ConnectTimeout=2 -o ServerAliveInterval=2 -o ServerAliveCountMax=3", so a
           connection that hangs after connecting, for example because the VM reboots, fails after ~6 seconds and is retried.)
          until ssh -o StrictHostKeyChecking=no -o ConnectTimeout=2 -o ServerAliveInterval=2 -o ServerAliveCountMax=3 "$USER@10.67.38.10" "true" 2>/dev/null; do
              sleep 2
          done

10. Configure chrony on host (time server for the VMs; chrony is installed in step 1):
   - Keep the original config once, then write the new one (the allow line is the bridge subnet, e.g. 10.67.38.0/24):
     if [ ! -f /etc/chrony/chrony.conf.bak ]; then sudo mv -f /etc/chrony/chrony.conf /etc/chrony/chrony.conf.bak; fi
     sudo tee /etc/chrony/chrony.conf <<EOF
# Use the local clock as a reference time source
local stratum 8

# Allow manual adjustments and use it for drift calculation
manual

# Allow VMs to connect
allow 10.67.38.0/24

# Record the rate at which the system clock gains/losses time
driftfile /var/lib/chrony/drift
EOF
   - Restart chrony and check it (the Ubuntu service name is 'chrony'; 'chronyd' is an alias of it):
     sudo systemctl restart chrony
     chronyc -n sources
     chronyc -n tracking

11. Configure /etc/hosts on host and inside node1:
    - Map node IPs in /etc/hosts on both the host and inside node1:
      echo -e "10.67.38.10\tnode1\n10.67.38.20\tnode2\n10.67.38.30\tnode3\n10.67.38.40\tnode4\n10.67.38.50\tnode5" | sudo tee -a /etc/hosts
      ssh "$USER@node1" 'echo -e "10.67.38.10\tnode1\n10.67.38.20\tnode2\n10.67.38.30\tnode3\n10.67.38.40\tnode4\n10.67.38.50\tnode5" | sudo tee -a /etc/hosts'

12. On node1 (Prepare Golden Node: OS update, containerd, chrony, Kubernetes packages, Longhorn prerequisites, and chrony config):
    i)   Update and upgrade all OS packages:
         sudo apt-get update && sudo apt-get upgrade -y

    ii)  Disable UFW firewall and disable swap:
         sudo ufw disable 2>/dev/null || true
         sudo swapoff -a
         sudo sed -i '/\sswap\s/s/^/#/' /etc/fstab

    iii) Configure kernel modules inside node1:
         sudo tee /etc/modules-load.d/k8s.conf <<EOF
overlay
br_netfilter
EOF
         sudo modprobe overlay
         sudo modprobe br_netfilter

    iv)  Configure sysctl settings inside node1:
         sudo tee /etc/sysctl.d/99-k8s.conf <<EOF
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
         sudo sysctl --system

    v)   Install containerd, qemu-guest-agent, and chrony:
         sudo apt-get update
         sudo apt-get install -y ca-certificates curl gpg apt-transport-https jq qemu-guest-agent chrony
         sudo systemctl enable --now qemu-guest-agent
         sudo install -m 0755 -d /etc/apt/keyrings
         sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
         sudo chmod a+r /etc/apt/keyrings/docker.asc
         sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
         sudo apt-get update
         sudo apt-get install -y containerd.io

    vi)  Generate default containerd configuration:
         sudo rm -rf /etc/containerd/config.toml
         sudo mkdir -p /etc/containerd
         containerd config default | sudo tee /etc/containerd/config.toml
    vii) In the generated /etc/containerd/config.toml, update:
         - SystemdCgroup = true:
           sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml
         - disabled_plugins = [] (ensures CRI plugin is active):
           sudo sed -i 's/disabled_plugins = .*/disabled_plugins = []/g' /etc/containerd/config.toml
    viii) Reload systemd daemon and restart containerd:
         sudo systemctl daemon-reload
         sudo systemctl restart containerd

    ix)  Install Kubernetes packages (kubelet, kubeadm, kubectl, cri-tools):
         sudo apt-get update
         sudo apt-get install -y apt-transport-https ca-certificates curl gpg
         sudo install -m 0755 -d /etc/apt/keyrings
         curl -fsSL "https://pkgs.k8s.io/core:/stable:/v1.37/deb/Release.key" | sudo gpg --dearmor --yes -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
         echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.37/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list
         sudo apt-get update
         sudo apt-get install -y kubelet kubeadm kubectl cri-tools
         sudo apt-mark hold kubelet kubeadm kubectl cri-tools
         sudo systemctl enable --now kubelet

    x)   Pull images with kubeadm and determine the pause image version:
         sudo kubeadm config images pull
         (Check which version of pause image is specified)
    xi)  Update the sandbox image in /etc/containerd/config.toml to match this version:
         sudo sed -i 's|sandbox_image = .*|sandbox_image = "registry.k8s.io/pause:3.10.2"|g' /etc/containerd/config.toml
         sudo sed -i 's|sandbox = .*|sandbox = "registry.k8s.io/pause:3.10.2"|g' /etc/containerd/config.toml
    xii) Reload systemd daemon and restart containerd:
         sudo systemctl daemon-reload
         sudo systemctl restart containerd
    xiii) Longhorn prerequisites on node1 (done before cloning, so every node inherits them; the 'systemctl stop/disable' lines
         may fail for units that do not exist on this Ubuntu release, e.g. multipath-tools-boot - the script ignores that):
         sudo apt-get update
         sudo apt-get install -y nfs-common
         for UNIT in multipathd.service multipathd.socket multipath-tools.service multipath-tools-boot.service; do
           sudo systemctl stop $UNIT
           sudo systemctl disable $UNIT
         done
         sudo modprobe dm_crypt
         echo dm_crypt | sudo tee /etc/modules-load.d/longhorn.conf
         sudo modprobe iscsi_tcp
         echo iscsi_tcp | sudo tee -a /etc/modules-load.d/longhorn.conf
         sudo modprobe nfs
         echo nfs | sudo tee -a /etc/modules-load.d/longhorn.conf
         sudo systemctl start iscsid
         sudo systemctl enable iscsid
    xiv) Generalize netplan configuration on node1 so all cloned VMs match their interfaces:
         sudo tee /etc/netplan/50-cloud-init.yaml <<EOF
network:
  version: 2
  ethernets:
    id0:
      match:
        name: "en*"
      dhcp4: true
      dhcp-identifier: mac
EOF
         sudo chmod 600 /etc/netplan/50-cloud-init.yaml
         sudo netplan apply
    xv)  Configure chrony on node1 to sync from the host (chrony is installed in item v; done before cloning, so every
         node inherits it). Keep the original config once, then write the new one (10.67.38.1 is BRIDGE_IPV4, the host
         address on virbr0 that the VMs reach):
         if [ ! -f /etc/chrony/chrony.conf.bak ]; then sudo mv -f /etc/chrony/chrony.conf /etc/chrony/chrony.conf.bak; fi
         sudo tee /etc/chrony/chrony.conf <<EOF
# Chrony server
server 10.67.38.1 iburst

# This directive records the rate at which the system clock gains or loses time.
driftfile /var/lib/chrony/chrony.drift

# If the clock offset is larger than 1 second, step it rather than slew.
makestep 1 3
EOF
         sudo systemctl restart chrony
         chronyc -n sources
         chronyc -n tracking
         (The Ubuntu service name is 'chrony'; 'chronyd' is an alias of it.)
         (BRIDGE_IPV4 is passed to node1 on the ssh command line, like KUBERNETES_VERSION: CHRONY_SERVER='<value of BRIDGE_IPV4>' bash -s)
    xvi) Exit out of node1 back to host machine.

13. Clone remaining nodes (node2 .. nodeN) from node1 (Golden Image):
    i)   Gracefully shut down node1:
         if [ "$(virsh domstate node1 2>/dev/null)" != "shut off" ]; then virsh shutdown node1 2>/dev/null || true; fi
         while [ "$(virsh domstate node1)" != "shut off" ]; do sleep 1; done
         sudo virsh change-media node1 sda --eject --config --force 2>/dev/null || true
    ii)  Register static DHCP reservations for all remaining nodes at creation time:
         sudo virsh net-update default add ip-dhcp-host "<host mac='52:54:00:10:00:14' name='node2' ip='10.67.38.20'/>" --live --config
         sudo virsh net-update default add ip-dhcp-host "<host mac='52:54:00:10:00:1e' name='node3' ip='10.67.38.30'/>" --live --config
         # (Repeat for any worker nodes, e.g. node4 [IP: 10.67.38.40, MAC: 52:54:00:10:00:28] and node5 [IP: 10.67.38.50, MAC: 52:54:00:10:00:32])
         (Note: MAC last octets are the hexadecimal equivalents of IP 4th octets: .10 -> 0a, .20 -> 14, .30 -> 1e, .40 -> 28, .50 -> 32).
    iii) Clone remaining node disks and VM domains from node1:
         sudo virt-clone -o node1 -n node2 -m 52:54:00:10:00:14 -f /var/lib/libvirt/images/node2.qcow2
         sudo virt-clone -o node1 -n node3 -m 52:54:00:10:00:1e -f /var/lib/libvirt/images/node3.qcow2
         # (Repeat for any worker nodes, e.g. node4 and node5)
    iv)  Start all virtual machines:
         virsh start node1
         virsh start node2
         virsh start node3
    v)   Personalize node2 (note its boot ID first, then set hostname, regenerate unique machine-id and SSH host keys, and reboot cleanly):
         ssh "$USER@node2" "cat /proc/sys/kernel/random/boot_id"
         ssh "$USER@node2" "sudo hostnamectl set-hostname node2 && sudo rm -f /etc/machine-id /var/lib/dbus/machine-id && sudo systemd-machine-id-setup && sudo rm -f /etc/ssh/ssh_host_* && sudo ssh-keygen -A && sudo reboot"
    vi)  Personalize node3 (note its boot ID first, then set hostname, regenerate unique machine-id and SSH host keys, and reboot cleanly):
         ssh "$USER@node3" "cat /proc/sys/kernel/random/boot_id"
         ssh "$USER@node3" "sudo hostnamectl set-hostname node3 && sudo rm -f /etc/machine-id /var/lib/dbus/machine-id && sudo systemd-machine-id-setup && sudo rm -f /etc/ssh/ssh_host_* && sudo ssh-keygen -A && sudo reboot"
         # (Repeat personalization for any worker nodes, e.g. node4 and node5)
    vii) Wait for all nodes (node1 .. nodeN) to boot/reboot, verify SSH connectivity and hostnames, and populate known_hosts:
         (For each clone, first wait until "cat /proc/sys/kernel/random/boot_id" over SSH returns a value different from the one noted
          before its reboot (the script gives up after 600 seconds), so that an answer from the still-running old boot is not taken as
          "rebooted". The polling ssh calls use ServerAliveInterval=2 and ServerAliveCountMax=3, see step 9 v.)
         until ssh -o StrictHostKeyChecking=no -o ConnectTimeout=2 -o ServerAliveInterval=2 -o ServerAliveCountMax=3 "$USER@node1" "hostname" 2>/dev/null; do sleep 1; done
         until ssh -o StrictHostKeyChecking=no -o ConnectTimeout=2 -o ServerAliveInterval=2 -o ServerAliveCountMax=3 "$USER@node2" "hostname" 2>/dev/null; do sleep 1; done
         until ssh -o StrictHostKeyChecking=no -o ConnectTimeout=2 -o ServerAliveInterval=2 -o ServerAliveCountMax=3 "$USER@node3" "hostname" 2>/dev/null; do sleep 1; done
         ssh-keyscan -H node1 node2 node3 >> ~/.ssh/known_hosts

14. For node1 (Bootstrap Control Plane):
    i)    Copy parameterized kubeadm-init-config.yaml (from backup/kubeadm-init-config.yaml) to node1
          (the deployment scripts embed this configuration instead of reading the file; backup/kubeadm-init-config.yaml is a reference copy):
          Substitute ${NODE1_IP} (10.67.38.10), ${VIP} (10.67.38.250), ${KUBERNETES_FULL_VERSION}
          (the full version of the kubeadm installed on node1, from 'kubeadm version -o short', for example v1.37.2;
           it is set as kubernetesVersion so kubeadm does not look up the latest version on dl.k8s.io), and ${CERT_SANS}
          (a YAML list including 127.0.0.1, localhost, 10.67.38.250, and each control plane's IP and hostname).
          (Do the substitutions in a copy of backup/kubeadm-init-config.yaml, then copy that file:)
          scp kubeadm-init-config.yaml node1:~/kubeadm-init-config.yaml
    ii)   Generate kube-vip static pod manifest on node1 in /tmp/kube-vip.yaml:
          INTERFACE=$(ip -4 route show default | awk '{print $5}' | head -n1)    # e.g. enp1s0
          KVVERSION=$(curl -sL https://api.github.com/repos/kube-vip/kube-vip/releases | jq -r ".[0].name" 2>/dev/null || echo "v1.3.0")
          sudo ctr image pull ghcr.io/kube-vip/kube-vip:$KVVERSION
          sudo mkdir -p /etc/kubernetes/manifests
          sudo ctr run --rm --net-host ghcr.io/kube-vip/kube-vip:$KVVERSION vip /kube-vip manifest pod \
              --interface "$INTERFACE" \
              --address 10.67.38.250 \
              --controlplane \
              --services \
              --arp \
              --leaderElection | sudo tee /tmp/kube-vip.yaml
          (Note: INTERFACE is the interface of node1's default route; the script falls back to enp1s0, the standard virtio
           network interface name in KVM virtual machines, if no default route is found.)
    iii)  Temporarily update hostPath to super-admin.conf in /tmp/kube-vip.yaml before placing in manifests:
          sudo sed -i '/hostPath:/{n;s/admin.conf/super-admin.conf/;}' /tmp/kube-vip.yaml
          sudo cp -f /tmp/kube-vip.yaml /etc/kubernetes/manifests/kube-vip.yaml
    iv)   Initialize control plane with kubeadm:
          sudo kubeadm init --config ./kubeadm-init-config.yaml --upload-certs
    v)    Note the token, discovery-token-ca-cert-hash, and certificate-key from the command output, e.g.:
          kubeadm join 10.67.38.250:6443 --token <TOKEN> \
              --discovery-token-ca-cert-hash sha256:<HASH> \
              --control-plane --certificate-key <CERT_KEY>
    vi)   Copy /etc/kubernetes/admin.conf to $HOME/.kube/config (as instructed by the command output).
    vii)  Verify API server is reachable and responds properly (e.g. kubectl get nodes).
    viii) Safely revert hostPath back to admin.conf:
          sudo sed -i '/hostPath:/{n;s/super-admin.conf/admin.conf/;}' /etc/kubernetes/manifests/kube-vip.yaml
    ix)   Move /etc/kubernetes/manifests/kube-vip.yaml to /tmp/
    x)    Stop and remove old kube-vip container to force static pod reload:
          sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock stopp $(sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock pods --name kube-vip -q 2>/dev/null) 2>/dev/null || true
          sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock rmp $(sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock pods --name kube-vip -q 2>/dev/null) 2>/dev/null || true
    xi)   Move /tmp/kube-vip.yaml back to /etc/kubernetes/manifests/
    xii)  Verify kube-vip pod is recreated and ready:
          until sudo crictl --runtime-endpoint unix:///run/containerd/containerd.sock pods --name kube-vip --state Ready -q 2>/dev/null | grep -q .; do sleep 2; done
          until kubectl get nodes >/dev/null 2>&1; do sleep 2; done
    xiii) Exit out of node1 back to host machine.

15. Copy Kubernetes admin config from node1 to host machine:
    mkdir -p $HOME/.kube
    scp "$USER@node1:/home/$USER/.kube/config" "$HOME/.kube/config"
    chmod 600 "$HOME/.kube/config"
    (Allows managing the cluster with kubectl directly from the host machine).

16. Update join configuration files on host:
    (The deployment scripts embed both join configurations instead of reading the files; backup/kubeadm-join-cp-config.yaml and
     backup/kubeadm-join-worker-config.yaml are reference copies. Do the updates in copies of them.)
    - Update a copy of backup/kubeadm-join-cp-config.yaml (kubeadm-join-cp-config.yaml) with the values noted in step 14.v (${JOIN_TOKEN}, ${CA_CERT_HASH}, ${CERT_KEY}, ${VIP}, and target ${NODE_IP}).
    - Update a copy of backup/kubeadm-join-worker-config.yaml (kubeadm-join-worker-config.yaml) with ${JOIN_TOKEN}, ${CA_CERT_HASH}, ${VIP}, and target ${NODE_IP}.

17. For remaining control plane nodes (node2 .. node${NUM_CP}) - Join Control Plane:
    For each remaining control plane node:
      i)   SCP the parameterized kubeadm-join-cp-config.yaml (from step 16 above) to the node.
      ii)  Run:
           sudo kubeadm join --config ./kubeadm-join-cp-config.yaml
      iii) Copy /etc/kubernetes/admin.conf to $HOME/.kube/config and set ownership:
           mkdir -p $HOME/.kube
           sudo cp -f /etc/kubernetes/admin.conf $HOME/.kube/config
           sudo chown $(id -u):$(id -g) $HOME/.kube/config
      iv)  Exit out of node back to host machine.

18. Distribute kube-vip manifest:
    Copy /etc/kubernetes/manifests/kube-vip.yaml from node1 to /etc/kubernetes/manifests/ on all remaining control plane nodes (node2 .. node${NUM_CP}).
    (Note: Do NOT distribute kube-vip to worker nodes).

19. For worker nodes (Join Worker Nodes) (if NUM_WORKER > 0):
    For each worker node (node${NUM_CP+1} .. node${TOTAL_NODES}):
      i)   SCP the parameterized kubeadm-join-worker-config.yaml (from step 16 above) to the worker node.
      ii)  Run:
           sudo kubeadm join --config ./kubeadm-join-worker-config.yaml
      iii) Exit out of node back to host machine.

20. Install the certificate check and renewal scripts on the control plane nodes:
    For each control plane node (node1 .. node${NUM_CP}); worker nodes get nothing. The files are in the certs/ folder next to the script:
      i)   SCP check_k8s_certs.sh, renew_k8s_control_plane_certs.sh, check_k8s_certs.service and check_k8s_certs.timer to /tmp on the node.
      ii)  Install the two scripts to /usr/local/bin (mode 0755) and the service and timer to /etc/systemd/system (mode 0644):
           sudo install -m 0755 /tmp/check_k8s_certs.sh /usr/local/bin/check_k8s_certs.sh
           sudo install -m 0755 /tmp/renew_k8s_control_plane_certs.sh /usr/local/bin/renew_k8s_control_plane_certs.sh
           sudo install -m 0644 /tmp/check_k8s_certs.service /etc/systemd/system/check_k8s_certs.service
           sudo install -m 0644 /tmp/check_k8s_certs.timer /etc/systemd/system/check_k8s_certs.timer
      iii) Set DEPLOY_USER in the installed renew_k8s_control_plane_certs.sh to $USER (the script also replaces that user's ~/.kube/config):
           sudo sed -i "s|^DEPLOY_USER=.*|DEPLOY_USER=\"$USER\"|" /usr/local/bin/renew_k8s_control_plane_certs.sh
      iv)  Remove the files from /tmp and enable the timer (it runs the check 2 hours after boot and then every 12 hours as root; the check runs
           renew_k8s_control_plane_certs.sh when a control plane certificate expires within 60 days):
           sudo systemctl daemon-reload
           sudo systemctl enable --now check_k8s_certs.timer
    (renew_k8s_kubelet_client_cert_from_host.sh, which renews the kubelet client certificate of one node, is not installed. Run it by hand on the host.
     Before that, set FIRST_NODE in the script to node1 (the deploy script does this in the repo copy of the script, so it changes the file on every run):
       sed -i "s|^FIRST_NODE=.*|FIRST_NODE=\"node1\"|" certs/renew_k8s_kubelet_client_cert_from_host.sh
       ./certs/renew_k8s_kubelet_client_cert_from_host.sh <node-name>)
    (renew_k8s_control_plane_certs_from_host.sh, which renews the control plane certificates of all control plane nodes from the host, is not installed. Run it by hand on the host.
     Before that, set FIRST_NODE, OTHER_CP_NODES and WORKER_NODES (space separated, may be empty) in the script (the deploy script does this in the repo copy of the script, so it changes the file on every run):
       sed -i -e "s|^FIRST_NODE=.*|FIRST_NODE=\"node1\"|" -e "s|^OTHER_CP_NODES=.*|OTHER_CP_NODES=\"<node2 .. node${NUM_CP}>\"|" -e "s|^WORKER_NODES=.*|WORKER_NODES=\"<worker nodes>\"|" certs/renew_k8s_control_plane_certs_from_host.sh
       ./certs/renew_k8s_control_plane_certs_from_host.sh
     It runs sudo /usr/local/bin/renew_k8s_control_plane_certs.sh on node1, copies /etc/kubernetes/admin.conf of node1 to ~/.kube/config on the host
     (the old one is kept as ~/.kube/_old_kube_config), runs the same renewal script on the other control plane nodes, then copies the new host
     ~/.kube/config to ~/.kube/config of the ssh user and of root on every worker node.)

21. Install host tools:
    On the host machine, install Cilium CLI, Helm, Kubectl, yq, chartmuseum, containerd with nerdctl and the CNI plugins, and BuildKit (each is skipped if already installed):
    i)   Install Cilium CLI:
         CILIUM_CLI_VERSION=$(curl -s https://raw.githubusercontent.com/cilium/cilium-cli/main/stable.txt)
         CLI_ARCH=amd64; if [ "$(uname -m)" = "aarch64" ]; then CLI_ARCH=arm64; fi
         curl -L --fail --progress-bar "https://github.com/cilium/cilium-cli/releases/download/${CILIUM_CLI_VERSION}/cilium-linux-${CLI_ARCH}.tar.gz" -o /tmp/cilium-linux-${CLI_ARCH}.tar.gz
         sudo tar xzvfC /tmp/cilium-linux-${CLI_ARCH}.tar.gz /usr/local/bin
         rm -f /tmp/cilium-linux-${CLI_ARCH}.tar.gz
    ii)  Install Helm via APT:
         sudo apt-get update -qq && sudo apt-get install -y -qq curl gpg apt-transport-https
         curl -fsSL https://packages.buildkite.com/helm-linux/helm-debian/gpgkey | gpg --dearmor | sudo tee /usr/share/keyrings/helm.gpg > /dev/null
         echo "deb [signed-by=/usr/share/keyrings/helm.gpg] https://packages.buildkite.com/helm-linux/helm-debian/any/ any main" | sudo tee /etc/apt/sources.list.d/helm-stable-debian.list
         sudo apt-get update -qq && sudo apt-get install -y helm
    iii) Install Kubectl via APT:
         curl -fsSL "https://pkgs.k8s.io/core:/stable:/${KUBERNETES_VERSION}/deb/Release.key" | sudo gpg --dearmor --yes -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
         echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/${KUBERNETES_VERSION}/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list
         sudo apt-get update -qq && sudo apt-get install -y kubectl
         sudo apt-mark hold kubectl
    iv)  Install yq (mikefarah/yq, latest release, SHA-256 verified):
         YQ_ARCH=amd64; if [ "$(uname -m)" = "aarch64" ]; then YQ_ARCH=arm64; fi
         YQ_BASE_URL="https://github.com/mikefarah/yq/releases/latest/download"
         YQ_BIN="yq_linux_${YQ_ARCH}"
         curl -L --fail --progress-bar "${YQ_BASE_URL}/${YQ_BIN}" -o /tmp/${YQ_BIN}
         curl -L --fail -s "${YQ_BASE_URL}/checksums" -o /tmp/yq_checksums
         curl -L --fail -s "${YQ_BASE_URL}/checksums_hashes_order" -o /tmp/yq_checksums_hashes_order
         # 'checksums' has one column per hash type (filename first); pick the SHA-256 column using 'checksums_hashes_order'
         YQ_SHA_LINE=$(grep -n -x 'SHA-256' /tmp/yq_checksums_hashes_order | head -n 1 | cut -d: -f1)
         awk -v bin="$YQ_BIN" -v col="$((YQ_SHA_LINE + 1))" '$1 == bin {print $col}' /tmp/yq_checksums
         sha256sum /tmp/${YQ_BIN}    # must match the value printed above
         sudo install -m 0755 /tmp/${YQ_BIN} /usr/local/bin/yq
         rm -f /tmp/${YQ_BIN} /tmp/yq_checksums /tmp/yq_checksums_hashes_order
    v)   Install chartmuseum (helm/chartmuseum, latest release, SHA-256 verified; skipped if /usr/local/bin/chartmuseum exists):
         CM_ARCH=amd64; if [ "$(uname -m)" = "aarch64" ]; then CM_ARCH=arm64; fi
         CM_TAG=$(curl -fsSL https://api.github.com/repos/helm/chartmuseum/releases/latest | grep '"tag_name":' | sed -E 's/.*"([^"]+)".*/\1/')
         CM_DIST="chartmuseum-${CM_TAG}-linux-${CM_ARCH}.tar.gz"
         curl -L --fail "https://get.helm.sh/${CM_DIST}" -o /tmp/${CM_DIST}
         curl -L --fail -s "https://get.helm.sh/${CM_DIST}.sha256sum" -o /tmp/${CM_DIST}.sha256sum
         awk '{print $1}' /tmp/${CM_DIST}.sha256sum
         sha256sum /tmp/${CM_DIST}    # must match the value printed above
         tar -xzf /tmp/${CM_DIST} -C /tmp
         sudo install -m 0755 /tmp/linux-${CM_ARCH}/chartmuseum /usr/local/bin/chartmuseum
         rm -rf /tmp/${CM_DIST} /tmp/${CM_DIST}.sha256sum /tmp/linux-${CM_ARCH}
    vi)  Install containerd, nerdctl, and the CNI plugins (same runtime setup as the golden node in step 12, without the Kubernetes-only parts:
         no pause image setting, no kubeadm image pre-pull, no kubelet / kubeadm / cri-tools, so Kubernetes can be added to the host later;
         each part is skipped if it is already in place, and existing files are kept unchanged):
         a) Kernel modules and sysctl settings (host steps 4 and 5 only cover vhost_net and ip_forward; the files are written only if missing):
              /etc/modules-load.d/k8s.conf: overlay, br_netfilter        sudo modprobe overlay; sudo modprobe br_netfilter
              /etc/sysctl.d/99-k8s.conf: net.bridge.bridge-nf-call-iptables = 1, net.bridge.bridge-nf-call-ip6tables = 1, net.ipv4.ip_forward = 1
              sudo sysctl --system
         b) containerd.io (skip if the package is installed); the Docker apt repository is added the same way as in step 12 v:
              sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
              (write /etc/apt/sources.list.d/docker.sources for the host's Ubuntu codename and architecture)
              sudo apt-get update -qq && sudo apt-get install -y containerd.io
         c) containerd config (skip if /etc/containerd/config.toml already has SystemdCgroup = true and disabled_plugins = []; an existing file is kept once as config.toml.bak):
              containerd config default | sudo tee /etc/containerd/config.toml
              sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml
              sudo sed -i 's/disabled_plugins = .*/disabled_plugins = []/g' /etc/containerd/config.toml
         d) nerdctl (latest release, minimal build, SHA-256 verified, installed to /usr/local/bin/nerdctl; skipped if that file exists;
            the tag is taken from the redirect of https://github.com/containerd/nerdctl/releases/latest, the archive and SHA256SUMS come from the release download URL),
            and /etc/nerdctl/nerdctl.toml with namespace = "k8s.io" (written only if missing).
         e) CNI plugins from the Kubernetes apt repository (skip if kubernetes-cni is installed; the repo is added as in step 12 ix if /etc/apt/sources.list.d/kubernetes.list is missing):
              sudo apt-get update -qq && sudo apt-get install -y kubernetes-cni      (installs to /opt/cni/bin)
         f) Reload systemd and enable containerd; restart it if the config changed in the containerd config part, otherwise just start it:
              sudo systemctl daemon-reload && sudo systemctl enable containerd && sudo systemctl restart containerd
    vii) Install BuildKit (latest moby/buildkit release; each part is skipped if it is already in place; the release has no checksum file,
         so the download is not checksum-verified):
         a) buildkit binaries (skip if /usr/local/bin/buildkitd exists); the tag comes from the redirect of github.com/moby/buildkit/releases/latest:
              BUILDKIT_TAG=$(curl -fsSL -o /dev/null -w '%{url_effective}' https://github.com/moby/buildkit/releases/latest); BUILDKIT_TAG=${BUILDKIT_TAG##*/}   # e.g. v0.35.0
              curl -L --fail --progress-bar https://github.com/moby/buildkit/releases/download/${BUILDKIT_TAG}/buildkit-${BUILDKIT_TAG}.linux-${ARCH}.tar.gz -o /tmp/buildkit.tar.gz
              sudo tar -xzf /tmp/buildkit.tar.gz -C /usr/local      (puts buildkitd, buildctl, ... into /usr/local/bin)
         b) /etc/systemd/system/buildkitd.service (written only if missing):
              [Unit]
              Description=buildkitd
              After=network-online.target firewalld.service containerd.service time-set.target
              Wants=network-online.target containerd.service
              [Service]
              Type=notify
              ExecStart=buildkitd
              TimeoutStartSec=0
              RestartSec=2
              Restart=always
              [Install]
              WantedBy=multi-user.target
         c) /etc/buildkit/buildkitd.toml (written only if missing; HOST_IP comes from inventory.txt or defaults to the bridge IP):
              [registry."${HOST_IP}:5000"]
                http = true
         d) Share the containerd systemd drop-ins (skip if the link exists; the target directory is created first so the link is never dangling):
              sudo mkdir -p /etc/systemd/system/containerd.service.d
              sudo ln -s /etc/systemd/system/containerd.service.d /etc/systemd/system/buildkitd.service.d
         e) Reload systemd and enable buildkitd; restart it if anything was installed or written in a) .. d), otherwise just start it:
              sudo systemctl daemon-reload && sudo systemctl enable buildkitd && sudo systemctl restart buildkitd

30. Install chartmuseum.service (local Helm chart repository on the host; HELM_REPO_SERVER_PORT and CHARTS_DIR come from
    inventory.txt: a port number (default 9000), and an absolute directory that ends with '/' (default: <script directory>/charts/);
    the script checks them at its start):
    i)   Create the charts directory (as the login user, so it is not owned by root):
         mkdir -p ${CHARTS_DIR}
    ii)  Write the unit file (overwriting an existing one; the two variables are replaced by their values):
         sudo tee /etc/systemd/system/chartmuseum.service <<EOF
[Unit]
Description=Chartmuseum for serving Helm charts locally
After=kubelet.service

[Service]
Type=exec
ExecStart=/usr/local/bin/chartmuseum --debug --port=${HELM_REPO_SERVER_PORT} --storage=local --storage-local-rootdir=${CHARTS_DIR}

LogLevelMax=notice

[Install]

         sudo systemctl daemon-reload
